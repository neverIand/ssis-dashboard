# Modernization plan

[The roadmap](roadmap.md) defines scope. [Progress](PROGRESS.md) owns milestone status and open gates; [API semantics](API_CONTRACT.md) and [OpenAPI](openapi.yaml) own the interface. This document records architectural decisions and future delivery boundaries.

## Architecture

Keep Python, Flask, pyodbc and useful checked-in SQL. Serve a read-only API and prebuilt browser assets from the same application origin. Organize functions around operations; introduce a class only when its state and lifecycle belong together. No ORM, extra application database or framework migration is required.

| Boundary | Responsibility |
| --- | --- |
| `dashboard/__init__.py`, `config.py` | Application construction and private configuration |
| `api.py`, `api_validation.py`, `errors.py` | HTTP inputs, capabilities, safe response/status handling |
| `frontend.py`, `templates/app/` | Native shell, validated packaged-entry assets, prefix-aware bootstrap URLs and build-failure response |
| `executions.py`, `navigation.py`, `metrics.py`, `timeline.py`, inspection/event/value/history modules | Resource-specific query coordination and DTO assembly |
| `db.py`, `query/` | Bound SQL, timeout settings and ownership of each connection/cursor |
| `timestamps.py`, `serialization.py`, `cursors.py` | Exact typed data, explicit JSON primitives and authenticated paging state |
| `ssis.py`, `views.py`, templates | Retained legacy presentation adapter |
| `web/` and `dashboard/static/app/` | Browser source/build inputs and ignored generated assets included in prepared deliveries |
| `web/src/api.js`, `bootstrap.js`, `display.js` | Same-origin requests and safe errors; metadata startup lifetime; typed display without changing wire values |
| `web/src/selection.js`, `filters.js` | Exact selection validation, immediate folder/project scope and draft/applied filters; table order, popovers, history and teardown |
| `web/src/catalog-search.js`, `navigation.js` | Cancellable search across bounded catalog pages, navigation DTO checks and explicit continuation/retry |
| `web/src/range-editor.js`, `time-range.js` | Calendar/exact-bound editing, configured-zone conversion, DST resolution and server-anchored presets |
| `web/src/overview.js`, `render-overview.js` | Current overview request generation, exact-bound resource sequencing, typed response checks and native DOM presentation |
| Future update detector/stream modules | Change detection, subscription ownership, bounded notifications and shutdown |

The initial mode is loopback under one configured SQL identity. Browser identity headers cannot select that identity. Separate query connections own their resources and use live catalog observations; a cursor is not a database snapshot. Read-only catalog access may create connection-local temporary tables; it must not modify SSISDB system objects or data.

## Data and legacy boundary

Keep the legacy adapter alongside the new API until replacement-screen parity. The API corrects mixed time cohorts, wildcard sentinels, formatted string types and unbounded reads; these corrections do not silently change the legacy parity baseline. Preserve actual NULL timings and unknown numeric codes. Child invocations are observations, and estimates remain separate from actual timing. [API semantics](API_CONTRACT.md) owns the detailed rules; [the operation matrix](API_ACCEPTANCE.md#operation-matrix) checks them.

## SQL and resource decisions

Ordinary execution sorts must seek/select the bounded page before metadata, logging and event enrichment. Global calculated sorts may calculate keys over the whole cohort; prefer narrow working rows where measurement supports it. Keep event aggregation isolated from unrelated joins. A bounded result does not bound source scans, repeated-key windows, permission checks or history-source growth.

Current measured choices—narrow calculated cohorts, cached ID selection/logging and constrained event join order—are recorded with their tradeoffs in [the SQL remedy results](API_ACCEPTANCE.md#c82b3-execution-query-remedies).

Validate source and temporary scans, actual rows, logical/LOB reads, materializations, spills, compilation, response size and elapsed time under representative identities. Retain verified reductions in work despite noisy small-catalog latency unless they cause a material regression or disproportionate complexity. Apply RECOMPILE only to query shapes with measured justification. Do not modify system indexes, use internal-table permission shortcuts, introduce NOLOCK or hide unmeasured work behind a result cache. [The workload protocol](API_ACCEPTANCE.md#workload-protocol) defines comparable measurements.

Preserve parameter binding, exact 100-ns timestamps, BIGINT strings and explicit serializers. Typed calls use the connection-local datetimeoffset converter; bind `sql_timestamp()` strings with `CONVERT(datetimeoffset(7), ?)` to preserve the seventh digit. Opt into explicit NULL binding with `declared_parameters=True` only when SQL declares every input type; retain legacy defaults for legacy queries. Each query closes cursor and connection, attempts both closes after failure, and records safe metadata after cleanup. Browser cancellation does not guarantee native SQL cancellation; driver timeouts and request/resource tests remain necessary.

## Frontend and dependency policy

Use vanilla ES modules, native DOM/events/fetch/EventSource, semantic HTML and authored CSS. **Vite is allowed** for development/HMR and production builds. **Chart/table libraries are allowed when their complexity is justified**: compare required interactions, accessibility, maintenance, bundle size, licensing and update/teardown behavior. Pin tools, keep lockfiles, bundle libraries locally and deploy prebuilt assets; server users should not need npm. Production makes no public requests for fonts, scripts or analytics.

Keep frontend pages simple and functional. Use concise labels and useful status messages; omit slogans, marketing taglines and decorative filler copy.

The native UI uses the revised neutral-grey/indigo design system. `web/src/styles.css` owns shared `--sd-*` palette and radius tokens: page `#f3f4f6`, surface `#fcfcfd`, text `#252d3a`, secondary `#566174`, border `#d6dbe3` and action `#3c56a6`. Use a 15 px base at default browser settings, system fonts, 4 px spacing increments, flat panels, compact controls and stronger package names/counts. Status badges retain text and use known numeric codes for restrained colour; unknown codes remain neutral. The shell supplies the page/section hierarchy, connected summary cards and a single toolbar pager per table. Narrow layouts stack filters and keep horizontal scrolling within the execution table. Keep this authored CSS shared by future native screens; no animation, theme switch or styling dependency is needed.

D1a uses a JS entry and Vite manifest with a relative asset base. Only `dashboard/static/app/` is generated/emptied; that output is ignored by Git and included in the prepared application delivery after building from the tracked `web/` source and lockfile. Development uses a loopback Vite harness and a same-origin `/api/v1` proxy to local Flask. The D1b Flask shell consumes the manifest through Flask's prefix-aware static endpoint, including CSS from shared imports and optional module preloads. Shell requests read build files without SQL; absent/invalid builds return a safe 503 without preventing legacy/API/health startup. The manifest is reread for each shell request so a repaired build takes effect without recreating the app. Bootstrap JSON contains only application/API/execution URL bases; D2a loads metadata separately and D2c owns execution/summary requests. Build commands, supported runtimes and packaged/ignored boundaries are in [installation](installation.md#build-the-browser-assets). Node's built-in test runner and existing Flask unittests provide focused coverage without another test dependency.

Successful native overview/detail shells send `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, including when mounted under a prefix. Templates use external same-origin scripts/styles and a non-executable JSON configuration block; chart tick positions use CSSOM property writes. Template/source guards reject inline styles, event handlers, executable inline scripts, HTML injection sinks and dynamic execution. The legacy pages and the shared `error.html` 503 fallback keep the framing-only policy; Fetch Metadata rejection, `nosniff` and `X-Frame-Options: DENY` still apply. Shells remain `no-store`. Only successful/conditional responses for `/static/app/assets/*` receive `Cache-Control: public, max-age=31536000, immutable`; dot-segment aliases escaping that directory, errors, `theme-init.js`, `LICENSES.txt`, `manifest.json` and legacy static resources retain their existing cache behavior. Independent native CSP/theme/chart checks remain required for the review-fix candidate.

The request boundary permits same-origin GETs within the supplied API base, rejects redirects and uses same-origin credentials with `no-store`. It preserves wire strings, encodes query values, checks JSON envelopes and exposes only fixed safe error messages, known problem codes and validated request IDs. Metadata supplies limits, statuses, sorts, capabilities and the display timezone; invalid or missing consumed settings stop startup without fallback configuration. One metadata owner coalesces concurrent starts, cancels after a 10-second browser deadline and offers manual Retry without an automatic loop. Disposal clears the timer, aborts transport and rejects late generations; back/forward-cache restoration creates a fresh owner. This lifetime is separate from the later overview refresh owner.

Replace jQuery with native events/fetch, Bootstrap/SmartMenus with authored layout and keyboard-accessible controls, DataTables with bounded server-backed tables, and Morris/Raphael with SVG or a justified chart library. Provide chart text/table alternatives and small authored icons. Remove legacy assets only after reference checks and parity. Target corporate Edge/Chrome; include Firefox/Safari smoke checks when used, with no IE requirement.

Keep filters, sorting, paging, scroll, focus, selected execution and chart state during refresh. Abort obsolete requests and check request generations so stale responses cannot overwrite a newer selection. Coalesce notifications, avoid overlapping fetch/poll loops, pause hidden work and resync on return. Retain useful stale data with clear retry/connection state. Render catalog text with `textContent`, format typed values with `Intl`, show the timezone, and store only display preferences locally.

### Overview state and refresh

Phase 3 has [nine implementation tasks](PROGRESS.md#phase-3--first-native-screen-preparation). Keep browser modules around operations that share state: applying a selection, requesting an overview, rendering typed values and owning refresh lifetime. One coordinator owns the applied selection, effective creation bounds, page-entry cursor path and request generation; rendering and transport helpers do not maintain competing copies. `refresh-loop.js` owns timer scheduling and observes coordinator cycles without owning data requests or catalog state. A framework, general state library or domain class hierarchy is unnecessary for this screen.

Separate draft filter inputs, applied selection and display preferences. Shareable `/app/` URLs contain validated selection/sort/limit; opaque cursors and catalog rows stay out of URLs and persistent storage. Back/forward restores the selection and an available valid in-memory page context; a fresh load starts on page one. “All folders/projects/statuses” omits the corresponding API parameter, so a literal name such as `all` remains selectable. The selection session owns canonical names restored from URLs or chosen from options. Labels use the exact strings; the single-line search field never replaces a selection unless the user chooses Use exact name. Project browsing reads the session's exact applied folder.

D2b's filter/history boundary uses the compact Folder / Project / Overview title row and Status/Created popovers. Batch B applies changed Status choices on Done, outside click or tabbing outside; Escape discards the draft and restores the trigger focus. Created presets apply in one click, and custom dates on Use range, with no separate Apply. Scope choices restart page one; changing the folder clears its dependent project, while a project row link sets both exact names together. Reset filters clears status/time and keeps scope and table order. Pointer selection actions consume an open Status draft in the same commit; detail anchors receive that selection before their click-triggered commit clears rows. Unchanged closes send no request. Invalid URLs expose Reset invalid filters without an applied fallback and clear the overview.

Catalog choices load only when a picker opens. Browsing without a term reads one name/ascending page at the advertised `default_limit` per Load more action. Search debounces input for 250 ms and scans at `max_limit`, stopping at exhaustion, another default-sized page of matches or a scan budget of `20 * default_limit` rows per search/Search more action, rounded up to a complete cursor page. With current 50/200 limits, that is at most five sequential requests for the same 1,000-row scan instead of twenty; this is a request-count bound, not a native latency measurement. Partial searches explicitly offer Search more. Project browsing requires a folder; Use exact name also supports a project across all folders. Each request has a 15-second deadline. Closing, replacing or disposing a search aborts work and rejects late generations. Expired cursors require a manual retry from page one; access denial clears choices. Keyboard continuation moves focus to newly added choices while respecting focus moved during the request.

The Created editor uses native date/time inputs in the global display timezone, prefilled from the current effective window. Date-only ranges include both selected dates; Include time makes the end exclusive. Blank bounds retain server-default semantics. Repeated local times require an explicit occurrence, while clock-change gaps are rejected. Exact timestamps remain available on demand; unchanged offsets and all seven fractional digits survive, and each bound independently tracks calendar or exact-text edits. Relative presets keep `created=24h|7d|30d|today` in the selection URL and detail return context. Each page-one cycle resolves explicit API bounds from the initial metadata or latest list server timestamp plus elapsed monotonic time, with maximum-span validation and no extra metadata read. Raw client wall time never anchors the window; explicit bookmarks and custom bounds remain absolute. Default window continues to use server defaults. No API/SQL or dependency change is introduced.

On each new cohort, use one execution response to establish exact `meta.from`/`to`, then request summary cards with those bounds. Summary remains all-status and is not a filtered-list total. An overview generation prevents stale responses from another selection from being displayed as current; separate API requests still observe live catalog state and do not form an atomic snapshot. Keep BIGINT IDs, wire timestamps and cursors unchanged; `Intl`/browser date conversion is for display only. Custom time inputs must resolve to explicit offsets rather than silently using the browser's timezone.

D2c implements the request and rendering owner. It validates consumed row types, bounds/order, unique identities and summary status groups/totals without another schema library. A selection change clears prior rows/cards, aborts the old request and rejects late generations. Each overview request has a 30-second browser deadline. Execution failure prevents subsequent resource requests; transient summary failure retains current rows and retries summary with the same exact bounds, followed by the open timeline as described below. Denied access clears all overview resources. Invalid selection/disposal clears the view, and identical concurrent applies coalesce. Rendering uses native text/time/link elements, distinguishes NULL/zero/unknown values and labels elapsed time separately from actual duration. The header groups title, load state, timezone and Legacy link into one desktop row with narrow-screen wrapping.

D2d uses metadata-advertised sorts and ascending/descending direction. Next/Previous fetch server order without local sorting or cached rows. Deeper continuations repeat exact effective bounds and verify unchanged cursor `as_of`/upper fence. Previous to page one re-resolves a relative preset; other selections retain bounds on Previous. Page one establishes a new fence because the API supplies no first-page entry cursor, then rebuilds its forward path. First page and applied filter/order/size changes start a fresh first-page cohort. Up to eight recent selection paths remain in memory for Back/Forward; history state, URLs and persistent storage contain no cursors or rows. Ordinary reload starts fresh. D3a implements manual Refresh through this owner. A pending refresh retains and marks existing rows/cards as previous observations. Network/deadline/HTTP transient failures retain those observations only for the same applied scope; malformed/rejected responses clear the affected stale data, and denied access clears displayed resources and paths. Newly returned list bounds must match before old cards can remain visible during a summary update. Resource generation times label previous observations; idle retained counts do not claim an active refresh. Relative windows use the server anchor described above. The renderer reuses execution-ID rows and links, patches typed cells and restores the completion-time scroll position and current row focus, with the table region as fallback when a focused row disappears. Browser scroll limits still apply when document height shrinks. Name columns retain a minimum readable width inside the scrolling table. Refresh clicks coalesce while any resource is active; applied changes replace a deeper refresh, while First page starts a fresh cohort only when idle. On `pagehide` all request owners are disposed. Only a browser-confirmed back/forward-cache entry retains an in-memory request-path/view-anchor checkpoint, excluding rows. Its return revalidates metadata and refetches the saved page before restoring its view. Ordinary navigation/reload starts on page one with URL selection restored. D3b adds polling and visibility recovery through the same refresh operation. D3c's available in-app browser checks pass; actual hidden-tab, cached-document and corporate-browser acceptance remain [open](PROGRESS.md#remaining-browser-acceptance).

The polling owner keeps one pending timeout, scheduled after the complete overview cycle, including the timeline when open. Delay is `min(300000, max(30000, ceil(cycle_ms * 5), failure_backoff_ms))`; transient-failure backoff is 30/60/120/240/300 seconds for consecutive failed cycles. Success resets the failure count. Nonretryable failure stops automatic requests pending explicit retry, selection change or pause/resume. Client wall time displays the next attempt; monotonic elapsed time measures work and advances the server anchor for relative windows. Manual work replaces the pending timer, and requests never overlap within an owner. Pause preserves manual refresh and survives selection changes. Resume refreshes immediately when idle or coalesces with active work. Hidden documents have no polling timer; an active cycle may finish while hidden or paused. Visible return requests one resync, queued after an active refresh or resource retry; an initial/restored/selection page load already covers return without another immediate cycle. User pause and nonretryable stopping take precedence over visibility recovery. The visibility listener, timer and requests share disposal. A browser-cache checkpoint retains pause in memory; fresh navigation/reload enables automatic updates again.

P4.6a adds a lazy creation timeline to this owner. An open timeline joins the serial list → all-status summary → selected-status timeline cycle; closing it restores the original two reads. Its query uses the list's exact effective bounds and applied folder/project/status, without list order, limit or cursor. Counts describe executions created within each bucket: an actual start and current success/failure belong to that creation cohort regardless of event time. The server owns zero filling, calendar boundaries, partial edges and DST; the client validates exact cohort/timezone/grain, contiguous UTC intervals and safe consistent counts up to the advertised maximum of 1,000. It never invents calendar boundaries or silently changes an excessive Hour request to Day.

The timeline renderer keeps chronological UTC-start-keyed SVG groups, a native bucket selector and a complete collapsible data table. Batch E shows succeeded/failed/other together as status-colored stacks; Other is the returned Created count minus Succeeded and Failed, with actual-start counts retained in the text/table alternative. Date/hour labels and a count scale describe the plotted cohort. The latest non-empty bucket is selected initially (the latest loaded bucket if all are zero); after a grain change an empty retained start uses the same fallback, while same-grain refresh preserves an intentionally selected empty bucket; hover, focus and Left/Right/Home/End expose complete values locally. Bucket selection adds no request or timer; a changed Day/Hour interval makes a new owned request. Refresh preserves selection, expansion, scroll and current focus. Changed effective bounds clear old counts before the replacement read; temporary same-cohort failures may retain a labeled previous observation. Malformed/400 responses clear the timeline alone, while 401/403 from any overview resource clear rows, cards and cursor paths. Summary failures remain independent and can still be followed by timeline loading; summary retry rereads both open resources without another list. Closing an active timeline aborts only that final read and rejects late results. In-memory checkpoints keep open/grain/selected UTC start and view anchors, excluding payloads; obsolete series choices are ignored. URLs/history/storage contain no chart results or choices. Actual visibility/cache acceptance remains separate.

Pagination controls remain focusable when a valid selection exists, including during refresh or after the last row disappears. `aria-disabled` communicates unavailable actions; the overview owner rejects busy or unavailable paging. Completing a refresh does not move focus back after the user has moved elsewhere. Native disabling remains appropriate when no selection exists or the owner is disposed.

| Trigger | Window and page behavior |
| --- | --- |
| Apply selection, sort or page-size change | Clear cursor history and request page one. The configured default window is resolved by the server, including `AS_OF_DATE`; explicit bounds remain fixed. |
| Refresh page one manually or by polling | Retain the selected filter mode, sort and size. Re-resolve the configured default window, or reuse explicit bounds; use the returned bounds for cards. Replace the old continuation path because this request establishes a new fence. |

| Return from a hidden tab | Unless user-paused or stopped after nonretryable failure, perform one refresh using the same page/window rules, then resume the single polling schedule. Coalesce with an initial/restored/selection page load; queue one resync after an active refresh. Do not create another polling owner. |

Manual refresh, polling and visibility recovery share one request lifecycle; abort obsolete work and independently reject late generations. Preserve stale data only for a transient failure within the same authorized selection, with its last-success state visible. Clear protected data on denied access, and never label a previous selection's rows/cards as the newly selected scope. Dispose timers, listeners and pending browser requests together; backend timeouts/resource acceptance still own native SQL cleanup. Phase 5 can later reuse this refresh operation for coalesced notifications without treating phase 3 polling as streaming acceptance.

**Legacy bookmark entry.** P4.7b registers a bounded `native=1` translator after browser isolation, before legacy handlers/SQL. The shared metadata loader, transport and display helpers serve both screens. `mountBootstrap` owns settings/status; `overview-screen.js` owns overview-only bindings, while detail mounts its own loader/renderer. A detail screen must not require hidden copies of overview filters or extend the overview coordinator with unrelated section state. Validate each new consumed metadata/DTO field, including the separate executable-result vocabulary, when its feature is introduced. IDs, paths, cursors and timestamp strings remain exact; only display projections use browser formatting.

**Execution lifetime.** One detail owner groups the execution ID, request generation, current authorized observation, visible section states and refresh lifetime. On an ID change it cancels and clears the old view; late success, failure or denial cannot affect a newer execution. Base detail loading gates follow-up sections. Missing/hidden or denied execution clears the whole execution view and stops automatic retries. A section capability denial clears that section without inventing permission to fetch it elsewhere; an execution-scoped 404 invalidates the displayed execution. A malformed response is not stale-success evidence. Transient failure may retain labeled prior observations only within the same execution and permitted section scope, with their response times visible.

Reuse the existing refresh scheduler around the detail operation. Manual refresh, polling and eligible visible return share one cycle; complete it before scheduling the next and coalesce repeated activation. One active section tab sits below the summary: Events, Executables, Package calls, Parameters, Overrides and History. Base detail loads first, then that permitted tab only: two serial reads per normal refresh. Standalone tab selection/paging uses one section request. Disabled-capability tabs stay visibly muted, share one visible policy line and keep their own described hints; they send zero requests. A narrow tab strip scrolls horizontally to keep the selected tab visible without moving the page. Each section keeps its own bounded query/cursor path; switching removes old rows and aborts obsolete section work, or replaces the pending section behind a base read. Do not give tables their own polling loops. Dispose the screen's requests, timers and listeners together on navigation; browser cancellation still does not prove native SQL cancellation.

Frontend review decision D1 stops automatic detail refresh when the latest successful base read has non-null `ended_at`. That cycle still completes its active tab; afterward there is no interval, transient-failure backoff or hidden-to-visible resync timer. Failed reads retain the previous terminal state even if protected data must be cleared. Manual Refresh still reads base plus active tab; tab changes, sort, paging, search and section Retry keep their existing request paths. ## Production live updates

SSE is the initial server-to-browser transport; WebSockets require a concrete bidirectional need. The transport and SSISDB change detector are separate responsibilities.

1. Use shared bounded/timed change detection per approved database/authorization scope. Detect new records **and updates to existing active executions**; a maximum execution ID alone misses transitions. Never keep an ODBC connection for the lifetime of a browser stream.
2. Own detector startup/shutdown explicitly and avoid debug-reloader duplicates. Define coordination before adding multiple workers; process-local queues do not provide cross-worker continuity, and cursors need one shared `API_CURSOR_SECRET_KEY`.
3. Send small authorized resource-change notifications, without raw messages, values or connection details. Coalesce client refetches and recheck subscription access on reconnect or identity expiry.
4. Define ordered event IDs, bounded replay and idempotent handling. Snapshot/subscription handoff must not lose changes. Unknown/expired IDs, restart, retention gaps and queue overflow require explicit resync.
5. Bound queues, subscribers, replay and message sizes. Disconnect or resync slow clients, send heartbeats, and release subscriptions on disconnect/navigation/shutdown.
6. Show connecting/live/reconnecting/paused/stale/polling state. Hidden-tab return requires resync. Fall back to data-only polling with backoff and no overlapping loops; stop polling when streaming recovers.

Validate buffering, compression, idle timeouts, heartbeats, URL prefixes and stream/API capacity on the chosen authenticated proxy and production server. A thread-per-stream server needs an explicit capacity budget. Measure database detection load and multi-tab behavior before choosing topology. Development HMR and an ordinary polling screen do not satisfy this production milestone.
