## Current entry points

There are eight active legacy route families in [views.py](../dashboard/views.py), and two native shells in [frontend.py](../dashboard/frontend.py). Commented example routes are inactive. There is no native standalone history shell or catch-all router. A native detail page reads its exact package identity from the authorized base execution before requesting history.

In the tables below, **Supported** means a current native workflow/destination exists, **Difference** records an intentional contract or presentation change, **Gap** means no equivalent entry point or field exists, and **Gated** means capability/environment checks still apply. P4.7b implements conversion for L01–L07's representable inputs; complete integrated acceptance remains P4.7c work.

`P` is the application's `SCRIPT_NAME` mount prefix, either empty or, for example, `/ops/monitor`. Paths below are relative to `P`. `F`, `J`, `S`, `K` and `I` stand for validated folder, project, status name, package name and execution ID. The destination column is the **implemented P4.7b rule**, subject to the validation rules below.

## P4.7b translation contract

Implemented in [legacy navigation](../dashboard/legacy_navigation.py), registered after browser isolation and before legacy handlers/SQL. Only L01–L07's representable inputs convert; L08 and the gaps below remain explicit. The following rules describe current behavior.

1. **Opt in while preserving bookmarks.** Recognized legacy GET/HEAD paths with no `native` marker keep their current legacy response. A single `native=1` requests translation before any monitor/SQL work; successful translation returns a temporary **302** with a local Location and `Cache-Control: no-store`. Offer an ordinary Open native link on supported legacy pages, so copying that link opts in and ordinary existing bookmarks still work. No cookie/global preference, automatic default-route redirect or legacy asset removal is part of P4.7b.
2. **Parse only the supported entry contract.** In translation mode the only query pair is `native=1`. Reject duplicates, unknown/empty keys or values, malformed UTF-8/percent encoding and NUL with a safe HTML **400**, before SQL. Do not reinterpret legacy query text as native filters/search. An unmatched path stays **404**; method and Host/fetch policy remain in force. Existing non-translation legacy query behavior is unchanged.
3. **Translate names conservatively.** Work from the router's decoded path arguments **before** legacy handlers' extra `unquote`; never decode again. Exact lowercase `all` omits that scope; it cannot identify a literal catalog name `all`. Other names must be nonempty valid Unicode, at most **100 UTF-16 units**, with no `*`, `%`, `_`, `[` or `]`, slash/backslash, control characters, replacement character U+FFFD or trailing ASCII space, and must not be the dot segments `.` or `..`. These conservative exclusions cover LIKE semantics, legacy width truncation, ambiguous/double decoding and browser path normalization. Do not trim or case-fold accepted names. `ALL` is an exact name, a space and literal `+` remain distinct, and ordinary Unicode/apostrophes remain exact. Unsupported names stay accessible through the retained legacy route or explicit native exact-name entry; do not enable API pattern inputs in the UI as a shortcut.
4. **Use fixed vocabularies.** Status names are case-sensitive: `all` → no status; `created=1`, `running=2`, `cancelled=3`, `failed=4`, `pending=5`, `halted=6`, `succeeded=7`, `stopping=8`, `completed=9`. Event kinds are exactly `all`, `errors`, `warnings`, `duplicate-warnings`, `memory-warnings`; `all` serializes as `#events`, others as `#events/<kind>`. Never treat a numeric status path token as a legacy status name.
5. **Keep IDs exact.** Validate the legacy integer ID in `1..9223372036854775807`, then serialize it as a canonical ASCII decimal string. The legacy converter already collapses aliases such as `00042`; normalize that known integer to `42`, without a JavaScript Number conversion. Zero/overflow is **400**; unmatched signed/fractional segments remain **404**. A syntactically valid ID does not prove existence/visibility: only the native API can establish that.
6. **Build destinations from the mount.** Use Flask endpoint URL generation, native `selectionSearch`/`executionHref` semantics and a query encoder, never root-string concatenation or caller-supplied hosts/return URLs. Native overview parameters are only `folder,project,status,created,from,to,sort,direction,limit`. Mapping emits only applicable folder/project/status; native defaults supply the remaining fields. Do not fabricate absolute dates from a client clock or copy ignored legacy `from/to`. For example, under `/ops/monitor`, `/folder/Finance/project/Load/status/failed?native=1` → `/ops/monitor/app/?folder=Finance&project=Load&status=4`.
7. **Carry no invented return state.** A standalone legacy execution/events/values URL has no applied overview context, so its native destination has no `overview` parameter. Overview return goes to `P/app/` at page one. Existing native links may still use their validated selection-only `overview` envelope; invalid/duplicate/arbitrary return URLs fall back there with the existing notice. No cursors, page numbers, rows, search text, values or messages enter the mapping URL/history/storage. Fragments contain section/category only.
8. **Keep unsupported conversion explicit and database-free.** An unrepresentable legacy scope (patterns, ambiguous decoded names or any L08 history URL) gets a safe HTML **409** explaining that native conversion is unavailable. Open legacy page uses the query-only relative link `?`: this clears the opt-in query while preserving the original path, percent escapes and mount, rather than reconstructing ambiguous names. Open native overview uses Flask URL generation. Invalid status/category/ID or translation query remains 400, never a broader overview redirect. The unsupported result performs no SQL or execution search. Do not add a native history shell or API resource as an incidental fix.
9. **Honor native policy after arrival.** Do not read metadata or SQL just to choose a redirect. The native screen revalidates settings, execution visibility and the active section. With a disabled capability its requested tab stays disabled, its visible disabled-section note remains, and the existing allowed default tab is selected without requesting the denied resource. A later section 403 clears that section; a missing/denied base clears the execution. Never redirect/fetch legacy automatically following a capability failure, missing asset or API error; existing explicit Legacy navigation remains a mode choice, not a Retry implementation.

Server-side mapping must agree with the current [selection](../web/src/selection.js) and [detail navigation](../web/src/detail-navigation.js) contracts. The conservative legacy-name exclusions restrict conversion only; they must not narrow current native exact-name support. Default window, grouping, tab and paging differences remain visible in the usage guide; a redirect guarantees a supported destination, not equality of historical row sets.
